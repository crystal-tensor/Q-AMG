# 架构与算法

## 目标与 SKY-001 的关系

参考的是“分层结构 + 构造过程”的公开设计思路，没有声称复现 SKY-001 的网络或训练集。官方公开的生成目标、递归拆分、潜空间绘图与细化并未给出可直接运行的完整代码；其博客也将可执行 CAD 操作与可编辑特征历史列为后续工作。[Skyfall 原文](https://skyfall.ai/blog/introducing-sky-001)

本项目自行设计量子结构先验和几何闭环，以受控机械语法提供可以实际执行的 B-rep 解码器。它不是从零训练的大规模 3D 基础模型，也没有从一张照片准确恢复内部机械结构的能力。

## 三条量子路线的取舍

| 路线 | 输入/输出 | 主要资源约束 | 当前决定 |
|---|---|---|---|
| 条件量子结构采样 / Born machine | 条件与电路 → 结构潜变量测量样本 | shots、参数训练、可训练性、离散数据规模 | 保留条件接口和上下文参数迁移；没有声称已训练通用结构分布 |
| 约束结构优化 / QAOA | 原问题 → Ising 哈密顿量 → 候选结构 | 编码、辅助变量、耦合路由、双比特误差和反馈往返 | 首版主线；可以直接检查能量与几何、替换后端和做强经典对照 |
| 量子扩散/ODE 求解 | 扩散动力学 → 量子状态 → 经典结果 | 稀疏性、条件数、非线性近似、容错深度、状态读出 | 保留研究方向；当前没有实现或宣称其速度收益 |

来源：[QAOA 原论文](https://arxiv.org/abs/1411.4028)、[Quantum Circuit Born Machine](https://arxiv.org/abs/1804.04168)、[量子扩散求解](https://arxiv.org/abs/2502.14252)、[官方 QAOA 实现流程](https://quantum.cloud.ibm.com/docs/en/tutorials/quantum-approximate-optimization-algorithm)。这些研究不构成本项目存在实际量子加速的证明。

## 原问题与编码

每一分类决策有两个候选。传动装配的五组是轴径、轴承规格、齿轮、座体层级、防护；夹持机构是夹爪、导向宽度、驱动、导轨组合、夹垫。

独热变量 `x[g,k]` 表示选择候选 `k`，每组恰选一个。目标由公开记录的候选分值和配对分值组成，约束包括轴承匹配和夹爪间距。分值是示意偏好与合成制造评分，不是实测成本、物理强度或价格。

```
E(x) = Σ c[g,k] x[g,k] + Σ w[i,j] xi xj
       + M Σg (Σk x[g,k] - 1)²
       + M Σ forbidden_pairs xi xj
       + M Σ forbidden_options xi
```

`M = 1 + Σ |候选成本| + Σ |软配对成本|`，大于软目标的整个变动范围。小规模测试枚举所有位串，独立比较原约束表达式、QUBO 展开和 `x=(1-Z)/2` 的 Ising 能量；对原问题与 QUBO 两条精确求解路径核对最优值。

不额外引入辅助变量。当前最多五组：独热为 6/8/10 比特。XY 混合保持每组一个激发；它减少独热违例，但不保证轴承、间隙等跨组约束自动成立。

第二种编码用 `x[g,0]=1-b[g]`、`x[g,1]=b[g]` 做精确代换，保持全部设计选项与能量，将所需逻辑量子比特降为 3/4/5。代换后使用 X 混合。原始测量位串与解码得到的独热结构编码同时记录，不能把扩展位串伪称成物理测量位数。

QAOA 电路交替施加目标哈密顿量相位与混合层。COBYLA 更新角度；目标能量来自测量样本，不用经典最优解或全态概率偷偷挑答案。模拟使用 QuantumBridge 原生设备或基于 QB 电路的 GPU 适配器执行。为保持可审计性，参数、每次调用的计数、后端类型、任务 ID、QASM 与选中候选的见证都保存。

## 几何反馈与层级

选择决定零件尺寸、形状、是否存在或父子层级。例如整体座与分体座改变零件数和树深度，导轨/驱动改变夹具子装配。几何不是一个整体网格上的颜色分区。

输入的齿轮包络限制由实际实体包围盒求值。如果选中候选超出包络，几何校验返回对应决策，转成禁止项，重新编码并再次调用量子后端。测试覆盖重载大齿轮先被采样、因几何限制被拒绝、第二轮测量生成小齿轮的全过程。

不明来源的实体干涉不会随意归罪于一个变量；无可靠反馈时只能检查其余测量候选或明确失败。不会在失败时悄悄用经典最优解替换量子结果。

## 噪声、硬件与资源

默认自动选本机 GPU：Torch 适配器执行经 QuantumBridge 原生编译的 `rz/sx/x/cx` 门，在 CUDA 或 Apple MPS 上演化复数量子态；概率读回与 Born 直方图采样在 CPU 上执行并记录成本。无受支持 GPU 则选 QB 原生 StatevectorDevice CPU。它是量子电路模拟器，不是经典最优解替代器，也不是物理量子处理器。QB 原生 CPU 与 GPU 结果交叉核对，另有手写 NumPy 非对易矩阵参照和禁止外部 SDK 导入的子进程测试。旧版本的概率差记录保留在历史证据中。后端只支持末端测量的静态门电路，其他指令明确报错。[PyTorch MPS 官方文档](https://docs.pytorch.org/docs/2.12/notes/mps.html)

超导参考门集为 `rz/sx/x/cx`，实际门集与耦合由适配器能力描述提供。路由后的物理比特数、编译深度、双比特门和 shots 都记录。`ancillas=0` 指问题编码未引入辅助变量，不表示拓扑路由没有空闲物理位。

参考噪声只有去极化和读出误差；没有覆盖真实设备的泄漏、串扰、相干误差、漂移或完整 T1/T2 校准。没有公司设备数据时，只能标为通用/参考噪声。不能据此预测公司的真机性能。

理想态向量的最低存储为 `16×2^n` 字节；噪声逐 shot 模拟成本还会增长。后端设置 4 GiB 本地内存上限和显式比特限制。超出容量时必须明确报错或采用记录成本的分解，不能截断变量、减少原任务或静默换求解器。

上述 16 字节对应 QB 原生 CPU 的 complex128；GPU 后端为 complex64，每振幅 8 字节，额外计入门作用的中间张量。两种精度在资源记录中分别标注，不能拿低精度 GPU 与高精度 CPU 耗时直接宣称量子优势。

已实现超容量分解：使用有上限的随机可行上下文（不优化目标），按容量分块；固定变量的软项化为常数/条件成本，跨块硬约束化为局部禁止项。逐块调用量子后端，完成一整轮量子更新后才允许返回全局结构。完整原问题不缩小，初始化、条件化与子问题计时均记录；复合结果标为条件测量组成，不冒充一次全寄存器测量。这是分块启发式，不保证全局最优。

## 统计边界

强经典参照同时使用原问题的分类结构与相同 QUBO，避免只比较暴力位串搜索。目标由独立参考最优值给出：可行且目标差距不超过 `5%×max(1,|optimum|)`。求解器只通过同一目标谓词决定是否停止，目标最优位串不传给量子求解器。

time-to-target 在整个测量批次返回并完成解码后才记为命中，不虚构 shot 内到达时间。失败与超时保留。速度比按实例聚合，使用实例为簇的配对 bootstrap。几何校验实际运行，不用缓存模型耗时假装端到端实测。

基准覆盖导入库已热、每实例构建/编译冷的情形；它不是从进程启动到文件导出的总时间。`generate` 的完整文件导出、拆解检查计时单独报告，首轮装载库的时间也必须另行披露。

## 复杂度与加速条件

若有 G 个二元结构决策，强经典枚举只需检查 `2^G` 个分类组合，而非独热位串的 `2^(2G)`。量子紧凑编码同样为 G 个比特，必须保留这一公平对照。

对 n 比特、m 个非零二体耦合、p 层 QAOA，路由前门数为 `O(p(n+m))`；实际深度和双比特门随拓扑路由变化。若优化 K 次、每次 S shots，还需计入约 `K×S` 次测量及主机循环；一般 QAOA 不保证比 CP-SAT 或其他结构化算法更快。纯状态向量模拟的空间随 `2^n` 增长；CPU/GPU 数值模拟加速不等于量子算法优势。

要在子流程达到 1.2 倍，必须满足 `T_QPU及往返 < T_最佳经典/1.2 - T_主机编码编译等开销`。若右侧为负，仅换更快的 QPU 仍不够，需要改变摊销方式、编码、算法或任务规模。当前只有 3–5 个分类变量的任务经典参考极快，不能把减少门数直接换算成端到端的量子加速倍数。


## Q-AMG 0.2：QB 原生迁移与通用图片入口

当前项目名为 **Q-AMG（Quantum-assisted Mechanical Generation）**。QuantumBridge 固定到公开提交 `e12cdbcbfc17fab83cc744b4d537746e428c99c8`。使用原生 Circuit、ParameterVector、transpile、StatevectorDevice、DensityMatrixDevice、噪声模型与序列化；应用环境不安装 Qiskit/Aer/PennyLane。原生 SDK 源码和许可随项目保存，用户本机另一个 QB 开发仓库未作修改。

QB 使用 q0-first 位序。GPU 适配器读取 QB 的控制/目标线序和 gate_matrix，按同一张量顺序演化；经典测量寄存器另行映射。QB 编译元数据保存于序列化 sidecar，标准 QASM 不承载的信息不会静默丢弃。[QB 原生源码](https://github.com/crystal-tensor/QuantumBridge/tree/e12cdbcbfc17fab83cc744b4d537746e428c99c8/quantumbridge)

图片入口使用固定版本的 [TripoSR](https://github.com/VAST-AI-Research/TripoSR)，它由单图预测三平面特征，再查询密度/颜色并提取等值面。原始权重不训练、不修改。项目对其增加 CPU marching cubes、本地 DINO 配置与延迟背景依赖；这些适配及许可在 vendor/SOURCES.json 中记录。背景由小型 U2NetP 估计，已有透明通道优先沿用。

```
图片 → 前景/参考标尺 → 本地 TripoSR → 封闭网格
     → 几何/颜色切面候选 → QB QAOA 采样
     → 实体分件 → 并集/对称差验证 → 展开/采样拆解/合并与恢复
```

`mesh_parts.py` 从形状截面和颜色差提出最多九个切面候选。每组二元选择表示保留连接或切开，QB 测量必须决定实际使用的切面。目标包含候选评分与软切面数量惩罚。该简化子目标可利用排序和遍历切面数进行强经典求解；当前规模非常容易，不能包装成量子优势实例。后续更丰富的语义相容性需要真实标注与实验。

`image_pipeline.py` 只接受来自本次采样的候选；切分后检查实体和并集对称差。Manifold 为切面封口，隐藏的截面内容仍是几何假设。合并使用真实网格布尔并集，结果保存为新运行，原分件与源图保留。参考标尺不等于测量尺寸；图片网格不声称有原生 CAD 特征历史、真实内部连接或制造认证。

神经模型在 GPU 上运行，缺少支持 GPU 时执行同一 CPU 模型。模型准备会固定权重、配置和校验值；图片推理阶段没有外部图片 API。冷/热启动、不同分辨率、CPU/GPU 与量子模拟/真机数据必须分别报告。
